# Runtime repair rationale

The reported usage record exposed acquisition retries, incompatible Unicode reservation units, repeated screening after core eligibility, insufficient phase budgeting, global bootstrap omissions and vague or recycled method proposals. Only generic software repairs and synthetic regression fixtures were carried into this release; private research artifacts and conversation transcripts are excluded.

## Changes and preserved boundaries

- Six independent literature adapters retain identities, versions, request provenance, download hashes and metadata/full-text distinctions. Case-study keyword injection was removed; new tasks use the reviewed topic queries.
- OpenAlex transport retains cache, server pauses and physical-request accounting. HTTP errors cannot silently reset a campaign or certify successful coverage.
- Prompt-bound budget recovery uses Unicode code points plus separately recorded UTF-8 bytes and hashes. Historical over-reservations cannot release spending capacity silently. Captain and cognition replays are idempotent and reject changed answers/identities.
- Reader eligibility is evaluated before optional breadth expansion. Required source, selection target, supplementary-document and independent reviewer gates remain. Scientific hypotheses are not fabricated as additional freeze prerequisites.
- Two zero-gain committed batches pause the target-gap strategy; unknown gain requires review. Reusing the same batch cannot increment its gain count.
- The opt-in Pro5x preset remains a short-session preset. New cognition configurations admit the nine required specialist assignments. Phase feasibility reports do not modify existing caps, renew a ledger or observe provider usage.
- New topic contracts require a committed final route selection, nearest-source mechanism comparison and concrete method card. Rejected mechanisms cannot be recommended. New no-candidate paths still reach independent final review. Legacy signed campaigns remain readable.
- The public personal Skill contains bootstrap resources; all four sibling Skills are still required. Install upgrades preserve research data and block unfinished signed jobs.
- Python 3.11 parsing and Windows newline behavior are explicit compatibility checks. New prompt files use LF; old Windows prompt hashes are checked against their signed logical UTF-8 text.

## Integrity

`original_v44_file_manifest.json` is unchanged provenance. `runtime_patch_manifest.json` records original and patched hashes plus reasons for explicit compatibility/utility changes, including Skill frontmatter and the cross-platform test fixture. Installer and doctor validate the overlay and fail closed on additional edits. `.gitattributes` prevents checkout newline conversion from invalidating byte-sensitive provenance. `SHA256SUMS.txt` contains tracked release files only.

## Verification boundary

Offline tests use synthetic model answers and network fixtures. They exercise retry/cache/pause behavior, source parsers, provider failover, Unicode recovery, evidence scheduling, route rejection and portable installation. They do not attest real independent model execution, research novelty or empirical effectiveness. A small live metadata smoke, when recorded, demonstrates only the queried endpoint and parser at that time.
