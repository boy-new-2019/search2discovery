# Project skills and release notes

- The public entrypoint is `$search2discovery`; internal engine versioned paths are compatibility interfaces.
- Distinguish candidate-record targets from achieved retrieval counts, metadata from full-text evidence, and offline tests from live Codex or scientific validation.
- PyMuPDF is optional and AGPL-3.0/commercial; `pypdf` is the permissive PDF text-extraction fallback. Neither library is vendored.
- For a bilingual GitHub landing page, place Simplified Chinese first, retain a complete English section, and add in-page language links.
- Before publishing, inspect the exact staged file set, run secret/data scans, review `git diff`, and verify the configured license and rights notes.

- Runtime repairs: preserve the immutable v4.4 manifest and use a separately verified hash overlay for declared source patches. Enforce LF checkout for byte-sensitive manifests.
- Windows prompt writers must use explicit LF; legacy signed prompt text may have CRLF on disk. Keep Unicode character budgets separate from UTF-8 bytes and retain historical over-reservations.
- Budget feasibility precedes optional breadth. Local caps are not provider quota. Ready core reading must not be starved by scientific questions misclassified as acquisition gates.
- New topic contracts require a signed final route/method card or an independently reviewed no-viable conclusion. Never recommend a candidate rejected by prior-art reviewers.
- Personal Skill bootstrap must work without the original repository path; test from an isolated personal directory with all four siblings.
- Python 3.12 Windows executable discovery applies PATHEXT rules to fixture paths; use an actual Python executable while retaining real subprocess argument and isolated-directory checks.
